# IndeXar - 个人知识档案库 项目定义文档

## 一、项目概述

**IndeXar** 是一个基于 Python 的桌面端个人知识档案库应用。其名称融合了 **Index**（索引）与 **Archive**（归档），直接指向系统的两大核心价值：强大的搜索能力和结构化的知识存储。

本项目的本质是：**一个读取本地 Markdown 文件、提供渲染阅览、支持全文搜索和内部链接跳转的单机桌面工具**。

它是你个人思想的私人维基百科——不是为团队协作而生，而是为一个人在信息碎片化的时代，将思考以结构化、可检索、完全私有的方式长期保存。

## 二、设计动机与核心理念

项目源于真实的个人需求：`.txt` 文件只能搜文件名，Word 文档臃肿且搜索局限于编辑器内。IndeXar 的设计遵循以下原则：

- **数据自主**：所有知识以纯文本 Markdown 格式存储在本地，用户对数据拥有绝对主权，不依赖任何云端服务或私有格式。
- **以阅读和检索为核心**：不做复杂的编辑功能（可用 Typora、VS Code 等专业编辑器），专注于“快速找到”和“沉浸阅读”两个场景。
- **轻量内敛**：界面简洁，功能聚焦，不追求花哨的视觉效果，服务于思考本身。
- **模块化分工**：获取知识用 AI/搜索，编写笔记用编辑器，归档与索引用 IndeXar。各司其职，互不替代。

## 三、技术栈

| 层级 | 技术选择 | 说明 |
| :--- | :--- | :--- |
| **开发语言** | Python 3.11 | 主力语言，生态成熟，学习成本低 |
| **图形界面** | Tkinter | Python 标准库，无需额外安装，满足基础桌面应用需求 |
| **数据存储** | Markdown 文件 + YAML 元数据 | 纯文本，人类可读，版本可控 |
| **Markdown 渲染** | `markdown` 库 + `tkinterweb` | 将 Markdown 文本转为 HTML 并在桌面界面中展示 |
| **元数据解析** | `python-frontmatter` | 解析文件头部的 YAML 元数据（标题、标签、重定向等） |
| **搜索（MVP）** | 遍历搜索（`for` 循环 + `in` 匹配） | 对于个人笔记数据量完全足够，实现极简 |
| **搜索（升级）** | `fuzzywuzzy` 或 `whoosh` | 可选升级，支持模糊搜索和索引优化 |
| **打包分发** | PyInstaller | 将应用打包为独立可执行文件 |

## 五、项目架构

```
IndeXar/
├── main.py              # 程序入口，初始化窗口并启动主循环
├── file_handler.py      # 文件读写模块，负责增删查和内容读取
├── search_engine.py     # 搜索模块，执行关键词匹配与结果返回
├── indexer.py           # 索引模块（可选），建立内存索引加速搜索
├── gui.py               # 图形界面模块，组装各组件并绑定事件
├── data/                # 笔记存储目录
│   └── welcome.md       # 测试用笔记
├── requirements.txt     # Python 依赖列表
└── README.md            # 本文件
```

**文件之间协作方式**：
- `main.py` 导入 `gui.py` 并启动主窗口
- `gui.py` 导入 `file_handler.py` 获取文件列表和内容
- `gui.py` 导入 `search_engine.py` 或 `indexer.py` 执行搜索并展示结果
- 所有 `.py` 文件通过 `import` 语句调用彼此的函数

## 六、MVP 开发路径

按以下顺序逐步推进，每一步都是一个可验证的里程碑：

1. **跑通“文件树 → 内容展示”**：点击左侧文件名 → 读取文件内容 → 渲染 Markdown → 展示在右侧。这是整个系统的第一根桩。
2. **实现内部链接跳转**：解析 `[[链接]]` 和 `[文本](./文件.md)` → 渲染为可点击元素 → 点击后触发 `open_note()`。
3. **实现全文搜索**：搜索框输入 → 遍历所有文件匹配 → 返回结果列表 → 点击结果跳转。
4. **加入索引（可选升级）**：启动时预建索引 → 搜索从遍历变为字典查询。
5. **加入重定向支持**：解析 `redirect` 元数据字段 → 自动跳转并显示来源提示。

## 八、可行性确认

本项目已通过以下维度的可行性评估：

1. **技术可行性**：所有核心功能均有成熟、文档完善的第三方库支持（`markdown`、`python-frontmatter`、`tkinterweb`），无需自研复杂算法。
2. **难度评估**：整体难度“中等偏简单”，对于有 Python 基础、无独立项目经验的开发者完全可以完成。核心本质是文件I/O + 字符串处理 + 界面组装。
3. **数据量安全**：个人笔记数据量存在生理上限（每天3000字，一年约20MB），纯文本遍历搜索的 O(n) 时间在此范围内完全可忽略不计。
4. **工作量评估**：核心功能约 4-6 周可完成，预留充足时间用于撰写论文和修改。
5. **风险可控**：不依赖后端服务、不涉及复杂算法、不追求“完美”，严格遵循 MVP 边界，功能明确且稳定。
